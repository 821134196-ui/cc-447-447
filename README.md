# 社区换热站供暖曲线与报修联动系统

管理换热站、楼栋、供回水温度/压力、循环泵、室外温度、运行班次、调节指令、
居民报修与处置回访的一体化运行平台。纯 Python 标准库 + 原生前端，**零第三方依赖**。

## 一条命令启动

```bash
python3 -m app.main
```

首次启动自动建库并**预置两天演示数据**（站点、4 栋楼、住户、48 小时测点读数、
班次与不可变快照、曲线版本、处于各生命周期的调节指令、报修/回访、七类事件、
交接记录与本地附件），同时启动：

- **模拟适配器**守护线程：每 5 秒按当前目标曲线叠加噪声持续产生仪表数据，
  并可经 `POST /api/sim/inject` 注入断点/温差/压降/水泵切换/冷态等异常；
- **进程内任务**线程：每 20 秒完成读数小时汇总与越限提醒扫描。

## 功能页面

1. **站点总览** — 快照哈希链状态、各生命周期指令计数、未结报修、七类事件分栏、
   楼栋实时供回水/压力/水泵、近 24h 报修密度微型条形。客服登录呈现脱敏服务视图。
2. **曲线编辑** — 折点表编辑目标供水/回水曲线，提交即生成只增版本（带 base_version
   乐观锁）；两名值班员基于同一版本提交时，**后提交者收到 409 冲突提示**并可刷新合并。
3. **实时趋势** — 原生 SVG 双面板（供回水 / 室外，各自独立纵轴），仅保留必要刻度、
   十字线 tooltip，可勾选多楼栋叠加比较。
4. **指令审批** — **上下分栏对照旧曲线与新曲线**（图形 + 折点变化表）；
   待复核 → 待执行 → 生效观察 → 结束；越限指令红框标注、必须经理批准；
   观察期内同楼栋冷暖报修自动关联并生成效果结论。
5. **报修聚合** — 密度表微型条形、重复报修自动归并主单、集中不热站点升级、
   处置与回访入口。
6. **班次交接** — 当前班次一键形成不可变快照（SHA-256 哈希链）、历史班次、
   交接记录与本地附件上传/下载。
7. **回访统计** — 满意率环、每日满意/不满意构成、待回访工单。

## 核心业务规则

- **运行快照不可覆盖**：`snapshots` 表由 SQLite 触发器禁止 `UPDATE`/`DELETE`，
  并以 `prev_hash` 串成 SHA-256 哈希链；`verify_chain` 可校验完整性。
  断点补录只新增 `source='backfill'` 的历史读数，不改动既有快照。
- **指令四态流转**：越限（供水 38–75℃、回水 30–55℃、温差 6–25℃ 之外）必须经理
  批准；运维只有执行权；观察期 90 分钟，期内关联同楼栋冷暖报修判定效果。
- **七类事件分开处置**：传感器断点（补录自动关闭）、温差异常（恢复自动关闭）、
  压力骤降、水泵切换、集中不热、重复报修、回访不满意，各有独立处置指引。
- **报修归并**：同住户同楼栋 24h 内重复报修归并主单并累加追访；60 分钟内 3 栋
  不同楼栋报不热自动升级集中不热；不满意回访独立开事件。
- **数据权限**：客服仅见脱敏姓名（张*）、电话（138****0001）、房号（1***），
  工艺接口对其返回 403；越权操作统一 403，未登录 401。

冷白底（#f4f7fa / #ffffff）+ 供水红（#d03b3b）+ 回水蓝（#2a78d6），
灰用于室外与中性信息；红蓝主色对通过色觉可辨识性校验（CVD ΔE 23.8）。

## 测试

```bash
python3 -m unittest discover -s tests -v
```

19 个用例覆盖题目要求的五个场景：

- **版本竞争**：两人同改一个版本 → 后提交者 409 `curve_conflict`，先提交版本保留；
- **断点补录**：超时距产生断点事件，补录落在窗口内自动关闭且快照不可 UPDATE/DELETE；
- **越限审批**：值班员/运维批准越限被拒，经理批准后运维才能执行，观察期效果判定；
- **报修归并**：重复报修归并主单、跨楼栋触发集中不热、不满意回访独立事件；
- **数据权限**：客服脱敏 + 工艺接口 403 + 未登录 401、运维不能批准但能执行。
